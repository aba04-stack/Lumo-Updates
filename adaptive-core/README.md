# Adaptive Core — модульная когнитивная исследовательская система

Экспериментальная основа для систем, которые объединяют общее рабочее пространство, долговременную память, модель своих возможностей, обратную связь и контролируемое развитие модулей.

## Архитектура v0.2

- **Stable Core** — неизменяемые версии стратегий, SQLite, журнал событий, валидаторы и правила продвижения.
- **Global Workspace** — ограниченный буфер сигналов, где внимание определяется приоритетом и оценкой надёжности; подписчики не могут сломать центральное состояние.
- **Episodic Memory** — сохраняет краткие итоги опыта, оценки и теги; поддерживает поиск по словам и тегам.
- **Self Model** — формирует отчёт о фактической результативности, количестве наблюдений, слабых местах и недавних сбоях. Это телеметрия системы, а не утверждение о субъективном самосознании.
- **Adaptive Runner** — цикл выполнения через внешнюю модель/инструмент, независимую оценку и запись опыта.
- **Evolution Manager** — принимает предложения конфигураций модулей, сравнивает кандидата с действующей версией на одинаковых тестах и активирует его только после прохождения quality gate.

## Самоулучшение без саморазрушения

Поведение системы может адаптироваться на основании оценённых результатов. Изменения модульных стратегий хранятся как новые версии, не заменяют старые и проходят проверку прежде, чем становятся активными. Ошибка исполнителя или оценщика не записывается как выдуманный балл.

Исполняемый Python-код автоматически не перезаписывается и не запускается из предложений модели. Улучшение реальных программных модулей должно приходить отдельными изменениями кода через review и CI. Это не позволит одному ошибочному предложению мгновенно повредить ядро.

## Связь с исследованиями сознания

Global Workspace, долговременная память, самонаблюдение и интеграция состояния — гипотезы о полезных функциональных свойствах для исследования когнитивных систем. Их наличие **не доказывает сознание**. v0.2 не обладает доказанным субъективным опытом и не делает таких заявлений. Мы можем проверять функциональные свойства, сравнивать архитектуры и фиксировать отрицательные результаты.

## Установка и проверки

Нужен Python 3.11+.

    python -m pip install -e "adaptive-core[dev]"
    python -m pytest adaptive-core/tests -q

## Интеграция

Создайте Store и AdaptiveCore, затем baseline для типа задачи. AdaptiveRunner получает функцию executor, которая вызывает модель/инструмент, и grader, который оценивает результат по независимым критериям и возвращает Assessment(score, success, metadata). Ядро выбирает стратегию и сохраняет измеренный результат.

Когда накоплена статистика, CognitiveSystem.register_module создаёт baseline конкретного модуля. Потом propose_module_revision принимает функцию proposer, которая создаёт новую конфигурацию, и evaluator, который проверяет кандидата на тех же тестовых случаях. Только подтверждённое улучшение активируется.

Не принимайте самооценку модели как единственный источник истины: предпочтительны детерминированные тесты, выполнение кода в изоляции, формальные проверки и независимая оценка. Не отправляйте в сторонние сервисы конфиденциальные данные без отдельной проверки приватности.

## Ограничения

- Ядро адаптирует выбор стратегий по фактическим оценкам и поддерживает проверяемые предложения изменений, но не переписывает собственную программу.
- Улучшение политики выбора не означает автоматического улучшения весов нейросети.
- Это не сознание и не доказательство сознания.
- Код не гарантирует отсутствия ошибок; он снижает риск повреждения принятой конфигурации и помогает обнаруживать регрессии.
- Не подключайте к ядру неограниченный доступ к shell, секретам или продакшен-среде.
