# Adaptive Core — безопасное адаптивное ядро

Экспериментальное ядро для систем, которые должны учиться на результате работы, выбирать более удачные стратегии и постепенно улучшаться без самоперезаписи исполняемого кода.

## Принцип

1. Система выбирает активную стратегию для класса задач.
2. Внешний исполнитель (модель или инструмент) выполняет задачу.
3. Независимый оценщик измеряет результат, а ядро сохраняет оценку в SQLite.
4. Выбор стратегии адаптируется по накопленной статистике.
5. Внешний proposer может подготовить новую версию инструкции/настроек, опираясь на агрегированную статистику.
6. Кандидат и действующая стратегия сравниваются на одних и тех же тестовых примерах.
7. Продвижение разрешается только при минимальном улучшении и ограниченном регрессе. В противном случае действующая стратегия остаётся нетронутой.

## Защита от поломок

- Ядро не изменяет собственный Python-код и не исполняет код кандидата.
- Стратегии неизменяемы: каждое изменение получает новый ID и новую запись.
- Все данные сохраняются в транзакционной SQLite-базе.
- Новая стратегия сначала проходит одинаковый набор оценочных примеров.
- Если оценщик падает, возвращает некорректный результат или проверка не пройдена, кандидат не активируется.
- Предыдущие активные стратегии сохраняются; новую можно отключить и вернуться к прежней.
- Результаты работы и решения о продвижении записываются в журнал событий.
- Сбой исполнителя или оценщика не превращается в выдуманный балл и не портит статистику.

## Что умеет v0.1

Это инженерный каркас адаптации: долговременная память о результатах, выбор стратегий по накопленным оценкам, рабочий цикл выполнения и обратной связи, интерфейс для генератора улучшений, проверяемое продвижение кандидатов и откат. Для решения реальных задач нужен внешний исполнитель, proposer и надёжный оценщик. Встроенной языковой модели и обучения весов нейросети пока нет.

Оценка кандидата настолько надёжна, насколько надёжен переданный оценщик. Для серьёзных задач используйте повторяемый тестовый набор, независимые метрики и отдельный скрытый контрольный набор, который не участвует в подборе стратегии.

## Запуск

Нужен Python 3.11 или новее.

Из корня репозитория установите пакет командой:

    python -m pip install -e "adaptive-core[dev]"

Запустите проверки:

    python -m pytest adaptive-core/tests -q

## Интеграция

Создайте Store и AdaptiveCore, затем baseline для типа задачи. AdaptiveRunner получает функцию executor, которая вызывает нужную модель/инструмент, и grader, который оценивает ответ по независимым критериям и возвращает Assessment(score, success, metadata). Ядро выбирает стратегию и сохраняет измеренный результат.

Когда накоплена статистика, передайте EvolutionManager функцию proposer: она получает текущую конфигурацию и агрегированные сведения о производительности и возвращает новую StrategyConfig. Метод propose_and_evaluate регистрирует эту конфигурацию как кандидата и передаёт её в quality gate. Только подтверждённое улучшение становится активной стратегией.

Не принимайте самооценку модели как единственный источник истины: предпочтительны детерминированные тесты, выполнение кода в изоляции, формальные проверки и независимая оценка. Внешний proposer не получает сырые пользовательские входы через встроенный интерфейс обратной связи; перед отправкой сведений стороннему сервису дополнительно проверьте приватность данных.

## Ограничения

- Ядро адаптирует выбор стратегий по фактическим оценкам и поддерживает проверяемые предложения изменений, но не переписывает собственную программу.
- Улучшение политики выбора не означает автоматического улучшения весов нейросети.
- Это не сознание и не доказательство сознания.
- Код не гарантирует отсутствия ошибок; он снижает риск повреждения принятой конфигурации и помогает обнаруживать регрессии.
- Не подключайте к ядру неограниченный доступ к shell, секретам или продакшен-среде.
