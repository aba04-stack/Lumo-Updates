# Adaptive Core — модульная когнитивная исследовательская система

Экспериментальная основа для систем, которые объединяют общее рабочее пространство, долговременную память, модель своих возможностей, обратную связь, доступ к открытым знаниям и контролируемое развитие модулей.

## Архитектура v0.3

- **Stable Core** — неизменяемые версии стратегий, SQLite, журнал событий, валидаторы и правила продвижения.
- **Global Workspace** — ограниченный буфер сигналов, где внимание определяется приоритетом и оценкой надёжности; подписчики не могут сломать центральное состояние.
- **Episodic Memory** — сохраняет краткие итоги опыта, оценки и теги; поддерживает поиск по словам и тегам.
- **Internet Knowledge** — по явному запросу ищет материалы через открытый API Википедии, сохраняет выдержки вместе с URL, языком, SHA-256 и временем получения, а затем ищет их локально. Сетевой доступ не запускается автоматически при создании системы.
- **Self Model** — формирует отчёт о фактической результативности, количестве наблюдений, слабых местах и недавних сбоях. Это телеметрия системы, а не утверждение о субъективном самосознании.
- **Adaptive Runner** — цикл выполнения через внешнюю модель/инструмент, независимую оценку и запись опыта.
- **Evolution Manager** — принимает предложения конфигураций модулей, сравнивает кандидата с действующей версией на одинаковых тестах и активирует его только после прохождения quality gate.

## Как использовать интернет-обучение

Интернет-коннектор использует открытый API Википедии и не требует API-ключа. Вызов обучения знаниям явный: CognitiveSystem.learn_from_internet("тема", language="ru", limit=5). После получения материалы сохраняются в отдельной SQLite-базе adaptive-web-knowledge.sqlite3; повторный поиск по уже полученным материалам не требует интернета: CognitiveSystem.reflect("research", web_query="нужная тема").

Внешний текст всегда имеет метку unverified_external_source; в рабочем пространстве он дополнительно помечается как непроверенный. Источник и контрольная сумма сохраняются для трассируемости. Это стартовый коннектор, а не полноценный универсальный поисковик всего интернета. Для важных фактов нужно сравнивать независимые источники и проверять даты.

## Самоулучшение без саморазрушения

Поведение системы может адаптироваться на основании оценённых результатов. Изменения модульных стратегий хранятся как новые версии, не заменяют старые и проходят проверку прежде, чем становятся активными. Ошибка исполнителя или оценщика не записывается как выдуманный балл.

Исполняемый Python-код автоматически не перезаписывается и не запускается из предложений модели. Улучшение реальных программных модулей должно приходить отдельными изменениями кода через review и CI. Это не позволит одному ошибочному предложению мгновенно повредить ядро.

## Связь с исследованиями сознания

Global Workspace, долговременная память, самонаблюдение и интеграция состояния — гипотезы о полезных функциональных свойствах для исследования когнитивных систем. Их наличие **не доказывает сознание**. v0.3 не обладает доказанным субъективным опытом и не делает таких заявлений. Мы можем проверять функциональные свойства, сравнивать архитектуры и фиксировать отрицательные результаты.

## Установка и проверки

Нужен Python 3.11+.

    python -m pip install -e "adaptive-core[dev]"
    python -m pytest adaptive-core/tests -q

Существующие тесты работают без доступа к интернету. Интернет-коннектор покрывается имитированными API-ответами; это проверяет логику, сохранение и обработку ошибок, но само по себе не подтверждает доступность удалённого сервиса.

## Интеграция

Создайте Store и AdaptiveCore, затем baseline для типа задачи. AdaptiveRunner получает функцию executor, которая вызывает модель/инструмент, и grader, который оценивает результат по независимым критериям и возвращает Assessment(score, success, metadata). Ядро выбирает стратегию и сохраняет измеренный результат.

Когда накоплена статистика, CognitiveSystem.register_module создаёт baseline конкретного модуля. Потом propose_module_revision принимает функцию proposer, которая создаёт новую конфигурацию, и evaluator, который проверяет кандидата на тех же тестовых случаях. Только подтверждённое улучшение активируется.

Интернет-коннектор пополняет поисковую память, а не параметры нейросети. Чтобы действительно обучать веса, всё ещё нужны модель, обучающий набор, целевая функция, вычислительные ресурсы и отдельная воспроизводимая оценка до/после. Не принимайте самооценку модели как единственный источник истины: предпочтительны детерминированные тесты, выполнение кода в изоляции, формальные проверки и независимая оценка. Не отправляйте в сторонние сервисы конфиденциальные данные без отдельной проверки приватности.

## Ограничения

- Ядро адаптирует выбор стратегий по фактическим оценкам и поддерживает проверяемые предложения изменений, но не переписывает собственную программу.
- Интернет-данные могут быть неполными, устаревшими, предвзятыми или ошибочными; метка источника не является доказательством истинности.
- Улучшение политики выбора или пополнение поиска не означает автоматического улучшения весов нейросети.
- Это не сознание и не доказательство сознания.
- Код не гарантирует отсутствия ошибок; он снижает риск повреждения принятой конфигурации и помогает обнаруживать регрессии.
- Не подключайте к ядру неограниченный доступ к shell, секретам или продакшен-среде.
